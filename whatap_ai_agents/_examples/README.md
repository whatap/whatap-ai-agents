# 에이전트 명세 예시

md 한 장이 에이전트 하나다. 이 폴더는 **읽고 베끼라고 있는 것**이고, 실행되지는 않는다.

| 파일 | 보여주는 것 |
|---|---|
| `01-minimal.md` | 최소 형태 — `description` 한 줄 + 본문 |
| `02-templated.md` | `params` 로 본문을 템플릿으로 만들기 (단발 분석 기능들이 전부 이 모양) |
| `03-structured.md` | `output_schema` 로 JSON 응답 강제하기 |
| `04-investigator.md` | 도구·위임·한계를 든 조사형 에이전트 |

## 이 폴더가 로드되지 않는 이유

카탈로그 로더는 **이름이 `teams` 인 디렉토리**를 전부 루트로 잡는다. 이 폴더에는
`teams` 가 없으므로 카탈로그에 들어가지 않는다 (`_drafts/` 도 같은 방식으로 빠져 있다).

**예시를 `teams/` 아래로 옮기면 그 순간 실제 에이전트가 된다.** 백엔드가 부를 수 있게
되고 대시보드에 트랜잭션이 생긴다. 옮기지 말 것.

## 이름은 선언하지 않는다 — 경로가 이름이다

```
whatap_ai_agents/v1/extra/teams/apm/active-stack.md   →   apm.active-stack
                                └팀┘ └─── 파일 ───┘
```

`teams` 위에 무엇이 있든(`v1/extra/` 같은 정리용 디렉토리) 이름은 안 바뀐다. 이름은
`teams` 바로 아래의 `<팀>/<파일>` 만 본다.

**이 이름이 그대로 와탭 트랜잭션 이름이고 백엔드가 부르는 값이다.** 파일을 옮기거나
이름을 바꾸면 대시보드 시계열이 끊기고 백엔드는 404 를 본다.

`name`, `team`, `prompt`, `source` 는 frontmatter 에 쓸 수 없다 — 전부 경로나 본문에서
정해진다. 쓰면 기동이 실패한다.

## frontmatter 에 쓸 수 있는 것 전부

필수는 `description` 하나다. 나머지는 전부 기본값이 있다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `description` | **필수** | 이 에이전트가 하는 일. 상위 에이전트가 위임 대상을 고를 때 읽는다 |
| `kind` | `agent` | `agent`(도구 들고 스스로 판단) / `workflow`(정해진 절차). **아래 주의 참고** |
| `model` | 런타임 기본값 | 모델 이름 |
| `temperature` | 런타임 기본값 | 0.0 ~ 2.0 |
| `max_output_tokens` | 런타임 기본값 | 응답 토큰 상한 |
| `thinking` | `false` | 추론 토큰 사용. **아래 주의 참고** |
| `params` | 없음 | 선언하면 본문이 Jinja2 템플릿이 된다 |
| `tools` | 없음 | 쓸 수 있는 도구 이름 |
| `subagents` | 없음 | 위임 대상. 같은 팀이면 이름만, 다른 팀이면 `팀.이름` |
| `max_steps` | `12` | 도구 루프 상한 (1~100) |
| `timeout_s` | 없음 | 조사 전체 제한시간 |
| `output_schema` | 없음 | md 기준 상대 경로의 JSON Schema |
| `prompt_version` | 본문 해시 | 대시보드에서 프롬프트 개정판을 가르는 값 |
| `labels` | 없음 | 관측용 문자열 태그 (`operation_type` 등) |

오타는 기동 시점에 잡힌다. `subagent:` 라고 잘못 쓰면 조용히 무시되는 게 아니라
**에러로 막고 쓸 수 있는 키 목록을 보여준다.**

## 주의 ① `kind` 에 "경계를 안 여는" 선택지는 없다

도구도 단계도 없이 모델을 한 번 부르는 실행이라면 감쌀 것이 없어 보인다. 그래도
`workflow` 로 연다.

와탭의 LLM 계측은 **부모 트랜잭션이 있을 때만** `[LLMAPI]` 를 여는데, 이 런타임은 조사
태스크에서 트레이스 컨텍스트를 일부러 끊는다. 우리가 경계를 열지 않으면 부모가 없고,
그 호출은 **와탭에 아예 기록되지 않는다.**

실제로 단발 호출을 경계 없이 돌렸다가 **60개 기능이 대시보드에서 통째로 안 보였다.**
`[Workflow]` 라는 이름이 다소 과하더라도 안 보이는 것보다 낫다.

## 주의 ② `thinking` 은 기본이 꺼짐이고, 켤 때는 이유가 있어야 한다

`thinking: true` 로 켠다. 켜면 느려지는 정도가 아니라 답이 깨질 수 있다.

실측 (qwen3.8-27b, 같은 판정 작업):

```
thinking: false     7.7초
thinking: true     76초,  추론에 3K 토큰을 소진하고 JSON 이 잘림 (finish_reason=length)
```

단발 분석 기능에서는 게이트웨이가 이 선언을 버리고 있던 버그 때문에 **한 요청이 237초**
걸렸고, 고친 뒤 **18~28초**가 됐다. 일부 기능은 300초 타임아웃으로 아예 실패했다.

- **끄는 게 기본이다.** 표를 읽고 정리하는 일, 번역, 분류에는 추론이 필요 없다.
- **켠다면 `max_output_tokens` 도 같이 올린다.** 추론이 같은 예산을 나눠 쓴다.
- **`output_schema` 와 함께 켤 때 특히 조심한다.** 잘린 JSON 은 파싱 실패로 나타난다.
- 도구를 들고 판단하는 조사형 에이전트가 추론이 도움 되는 드문 경우다. 다만 홉마다
  붙으므로 비용·지연이 곱으로 늘어난다.

## 새 에이전트를 실제로 추가하려면

1. `v1/extra/teams/<팀>/<이름>.md` 로 파일을 만든다 (팀·파일명은 소문자 슬러그)
2. `description` 과 본문을 쓴다
3. 런타임을 재기동하고 `/readyz` 가 `catalog: true` 인지 본다

이름이 겹치면 **카탈로그 전체가 로드에 실패한다** (조용히 하나를 덮지 않는다).
